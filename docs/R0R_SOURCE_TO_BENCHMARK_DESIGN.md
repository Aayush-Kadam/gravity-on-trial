# Source-to-benchmark design

Implemented command: `python benchmark_setup.py bootstrap --from-official-sources`. Verification: `python benchmark_setup.py verify`. The supported tested platform is Windows with Python 3.12 and the exact dependency lock. No GPU, Docker, WSL, MCMC or uncontrolled parallel inference.

The runner checks installed versions and frozen source/config hashes, creates .bootstrap/build-v1/ from distributable source/configuration files only, acquires official sources there, independently validates fixed-width parsing against whitespace tokens, writes the normalized catalog and feature inventory, and invokes the unchanged M2 evaluate and M3 one_scenario functions. Every original galaxy and all fourteen M3 scenarios are retained. The pipeline then runs the existing aggregate, independent scalar classification audit, full force/likelihood validation and scientific-figure generator. Application manifests and a receipt are generated from those new local results.

Scientific cache identity covers frozen model/inference/configuration files, bootstrap/aggregate/validation/plot code, the dependency lock and source acquisition references. Presentation-only code is separately covered by the final publication manifest; changing an app label does not change fit definitions. The new content revision is not falsely reported as the old M3 run's byte identity. Original seeds, starts, priors, bounds, masks, likelihood conventions and failure classifications remain intact.

Five-galaxy serial subprocess batches are bounded by memory, system headroom and time. Each final checkpoint is JSON plus a SHA-256 seal: the seal is staged first, then the completed JSON is atomically promoted. Temporary/partial files are not accepted as complete records. A resume checks identity, seal and full scientific schema before reusing records. Active-PID locks prevent concurrent setup; dead-process locks permit recovery. No existing validated result tree is overwritten. An existing unrelated/nonempty result tree is refused with instructions to use another source directory.

All complete result inventories/manifests are validated before an atomic directory promotion into results/. Preexisting empty setup directories are archived, not deleted. Verified raw inputs and the identity record are installed before the ready receipt becomes visible. The app checks receipt/input/manifest hashes before loading; missing setup presents instructions instead of synthetic data. Per-artifact adapters retain hash checks, and corrupt/missing records receive actionable errors. Rerunning successful setup verifies the existing tree and returns ALREADY_COMPLETE without fitting or contacting sources again.

Public files contain source, configuration, code/data hashes, dependency notices and setup instructions. Acquired observations and regenerated result arrays/figures remain local and ignored. File hashes detect corruption; unsigned manifests are not externally anchored authenticity proofs.
