# Gate 0 regression audit v2 — floating-point tie selection

The first report-generation audit introduced an additional 1e-8 km/s absolute check between the selected old and new curves. This check was not the frozen same-implementation fresh-process reproducibility criterion. It failed for DDO154 NFW: maximum selected prediction difference 8.690560235891098e-7 km/s; chi-squared changed by −2.842170943040401e-14. The failure was investigated before issuing any verdict.

Root cause: all four optimizer starts produce **exactly identical parameter arrays in the old and new engine**. The old objective summary uses np.sum(residual**2), whereas M1 uses a dot product. For starts 1 and 4 the old summaries tie at 117.71208076222494, choosing the first. New summaries are 117.71208076222493 and 117.71208076222491, choosing the fourth. These machine-precision differences select among unchanged nearly equivalent candidates. This is not a changed force calculation, data mask, unit convention or optimization trajectory. The maximum selected parameter change is about 2e-7 dex. All other selected old/new curves match exactly.

Audit v2 does **not loosen** the original reproducibility tolerance. It requires exact equality of every old/new per-start parameter array for all ten old halo fits, plus the frozen chi-squared tolerance. It reports any selected-curve difference explicitly rather than applying an unjustified exact-winner expectation across different reduction implementations. This stronger trajectory-level check passes. M1 fresh-process comparisons use the same implementation, and all arrays match exactly under the unchanged 1e-10 tolerances. Old artifacts remain unchanged.
