# R0 security and privacy

Explicit publication inventory was scanned for token/key patterns, private-key headers, secret assignments, developer usernames, user-home absolute paths, binary/private artifacts and cache/log directories. The initial source-only M4 snapshot produced no pattern findings. No secret value was printed. There is no Git repository/history, so tracked-history inspection is not applicable. Local raw data, full scientific outputs, browser profiles, logs, downloaded evidence, environments, executables and caches are excluded by the release allowlist and .gitignore. Generic Program Files/Edge paths are documented Windows platform requirements, not developer-home paths.

The declared clean dependency environment had OSV matches in Pillow 12.3.0, Starlette 0.49.3 and pytest 8.3.4. Details, aliases and severity metadata are retained; matches are not proof that this local app exposes each vulnerable path. Publisher/database severity can differ. The app has no image-upload feature and is localhost-only, but dependency findings were not waived for a public candidate. Streamlit 1.63.0 constrained Pillow below the identified fixed release. In a separate environment/snapshot, Streamlit 1.66.1, Pillow 13.0.0, Starlette 1.10.0 and pytest 9.2.0 resolved compatibly. All 107 tests and real browser workflows passed. A fresh OSV check of 47 runtime/test distributions returned zero matches at audit time. No vulnerability-free guarantee or penetration test is claimed.

A Windows virtual-environment redirector exposed a real monitoring gap: the original supervisor measured its small launcher process instead of the application descendants. The initial 4 MiB figure is explicitly invalid as app memory evidence. R0 candidate m4_serve.py/m4_fit.py use r0_processes.py to account for and stop only their owned descendant trees; memory floors, caps and time limits remain enforced. A separate import-directory fix uses parents=True for missing results folders. These targeted release patches are isolated; protected M4 and scientific source remain unchanged. Candidate process-tree accounting was verified through actual Windows startup/browser/restart. Summed per-process high-water marks are a conservative upper bound, not simultaneous RSS. Existing M4 direct-interpreter measurements are not retroactively replaced.

The candidate remains local/single-user and binds 127.0.0.1. No authentication, internet service hardening, multi-user threat model or public-hosting security claim. Dynamic user selections use catalog/allowlisted paths; no arbitrary upload or shell execution control is offered. Downloadable records reflect real local data. No credentials or binary libraries are bundled. Dependency notices remain retained. Final exact publication manifest/security results are in results/r0/v1/public_release_manifest.json and public_snapshot_security.json.

Primary advisories: [Pillow example](https://github.com/python-pillow/Pillow/security/advisories/GHSA-22hg-r758-rrw9), [Starlette form-limit advisory](https://github.com/Kludex/starlette/security/advisories/GHSA-82w8-qh3p-5jfq). Complete OSV records are private audit evidence. Patched requirements are intended for the R0 candidate, not a claim that the old M4 dependency declarations were rewritten.
